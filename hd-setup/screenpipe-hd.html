01overview

Screenpipe records the screen, audio, and UI events of a machine continuously, locally, and privately, then makes that record searchable and actionable by AI. The product is three verbs — Record, Rewind, Ask — and the roadmap runs from desktop memory (now) to the context layer for AI agents (next) to recording everything, 24/7, encrypted (later).

The monorepo is a Rust workspace of 19 crates plus a Tauri desktop app, five TypeScript packages, and an enterprise tree. Capture is accessibility-tree-first with OCR fallback; everything lands in a local SQLite database behind a localhost REST API that the app, CLI, MCP server, SDK, and browser extension all consume.

02architecture

One pipeline, three capture modalities, one store, many surfaces. The engine is compiled into the desktop app (in-process, not a sidecar) and also ships as a standalone binary. Privacy machinery — async PII redaction, vault encryption, keychain-backed secrets — sits beside the hot path, never on it.

03capture stack

Eight crates, ~60k source lines. Vision is paired-capture: a screenshot and an accessibility-tree walk are taken together (200ms hard timeout for Electron-style deep trees), OCR fills in when the tree comes up short. Audio runs a full VAD → transcription → diarization → speaker-clustering pipeline with four interchangeable ASR backends. On-device ML is first-class on Apple Silicon.

04data & intelligence

Eleven crates around one SQLite database and one HTTP server. The engine serves 25 route modules (~13.6k lines) on 127.0.0.1:3030; recent work unified artifact retrieval under GET /artifacts. Three distinct encryption domains protect data at rest, secrets, and sync — each with its own key model.

storage & api

  • screenpipe-db — SQLite + FTS5 + sqlite-vec; 90 migrations (2,456 lines) spanning Jul 2024 → Jun 2026; 20+ tables: frames, audio_transcriptions, ocr_text, ui_events, elements, meetings, memories, pipe_executions; write-queue with disk-I/O wedge recovery.
  • screenpipe-engine — axum, hot-frame LRU cache, jemalloc (non-Windows), memory watchdog, OpenAPI export at /openapi.yaml; runs standalone as the CLI daemon.
  • screenpipe-events — in-memory tokio broadcast pub/sub (meeting, power, workflow, permission, pipe events); 10-minute inactivity pruning.
  • screenpipe-config — TOML settings in ~/.screenpipe/; device-tier detection (Low/Mid/High by RAM) tunes capture aggressiveness.

privacy & sync

  • screenpipe-redact — async reconciliation worker off the capture path. Text: regex → Tinfoil confidential-compute enclave (SEV-SNP attestation) → local ONNX xlm-roberta (~280MB INT8, CoreML/DirectML/CPU). Image: RF-DETR + pixel masking. Hash-cached.
  • screenpipe-vault — user-initiated at-rest encryption of the whole data dir; Argon2 → ChaCha20-Poly1305.
  • screenpipe-secrets — AES-256-GCM secrets table, keys in the OS keychain; OAuth tokens migrated out of plaintext (PR #3986).
  • screenpipe-sync — schema-free ticketed pipeline (presign → PUT → manifest); per-recipient key wrap; bytes-pool reuse so a 50MB retry costs 50MB, not 150MB.
  • screenpipe-connect — 65 integration connectors: Slack, Telegram, Discord, Gmail, Notion, Linear, Jira, Salesforce, HubSpot, Calendly, Stripe, SSH/SFTP, mDNS, MCP servers…
  • screenpipe-team-memory — MCP-shaped memory files (YAML frontmatter + markdown) with compute-provenance tracking (tier, model, attestation) for audit.

05desktop app

Tauri 2.11.2 shell around a Next.js 15 frontend — 427 TypeScript files (165 components, 153 lib utilities) and 77 Rust modules (main.rs ~2.0k lines, commands.rs ~3.5k). The capture engine compiles directly into the app binary; the same port-3030 API the ecosystem uses is what the frontend talks to, with bearer-token auth and WebSockets for live events.

09risk register

Consolidated from per-subsystem surveys; ordered by blast radius. Several have spec'd fixes (vision pipeline v2, pipe execution) not yet fully landed.

capture · openOCR can block the capture loop

process_max_average_frame() runs synchronously inside the capture loop — 2–5s stalls under load; frame hashing false-matches at 320×180 after bursts. Decoupled OCR worker is spec'd (vision v2), not live.

capture · openframe-drop race + health misreporting

frame_write_tracker can silently skip frames that passed OCR; meanwhile /health may report "recording" with last_frame_timestamp 6+ minutes stale — the tray looks green while the pipeline is wedged.

audio · opencoreaudio tap orphaning wedges system audio

VisionManager shutdown can orphan the CoreAudio process tap (#3942) requiring a hard relaunch; capture also wedges silently during disk-I/O stalls (#3939). Recovery watchdogs are incomplete. Mic echo cancellation currently disabled in VPIO (#3938).

pipes · openpipe execution has no timeout and weak PID tracking

Hung subprocess blocks the scheduler indefinitely (wait_with_output, no deadline); child PID never written back (ExecutionHandle{pid:0}) so cancellation is unreliable; scheduler last_run is in-memory only and lost on restart.

privacy · designredaction is eventually-consistent and conservatively configured

Async reconciliation means captured text is searchable before redaction catches up, the elements table isn't reconciled yet (#3993), and pii_redaction_labels defaults to ["secret"] only — emails/phones require opt-in.

privacy · designvault has no recovery; sync key wrap lives in the database

Forgotten vault password is unrecoverable by design; the cloud-sync recovery key is stored in the same database it protects, so DB compromise spans recipients.

surface · reviewlocalhost attack surface

/cloud_proxy shows no visible auth scoping; the browser extension executes JS in tabs over un-TLS'd localhost WebSocket; Keychain cookie inheritance is readable by any process in the user session.

platform · watchplatform fragmentation tax

Three redaction backends (CoreML/DirectML/CPU) need per-platform CI toggles; MLX and Apple Intelligence are Apple-Silicon-only; ONNX runtime strategy differs per OS; Linux accessibility-tree parsing is still a placeholder.

build · watchdependency-fork and tauri-unstable exposure

Five patched upstream forks (cpal, whisper-rs, vad-rs, sck-rs, muda) must track upstream; the app uses Tauri's unstable child-webview feature, a hazard for the next major bump. ee/sdk keeps a separate lockfile — drift risk against core crates.

infra · monitorcloud pipes just migrated runners

Docker infra reverted in favor of org runners (enterprise-build only, commit 8c2bbc7); runner-image stability and cost/resource limits aren't documented yet.
